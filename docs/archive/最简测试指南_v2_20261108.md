## 为什么必须"一键闭环"，而不是等自动收信

代码里：自动轮询 `poll_once()` **不带 cycle_id**，收进来的候选人不归属任何一轮；只有 `run_daily_cycle()`（对应 `/recruitment/run`）才会在同一轮里完成「收信 → 筛选 → 打包发飞书」。如果让自动轮询先把邮件收走，再跑闭环就会查出 0 个候选人、包是空的。

所以测试期关掉自动轮询，改用 **`一键跑完整闭环.bat`** 一次点完，反而最简单、最可控。测完想恢复自动，把 `.env` 的 `INBOUND_POLL_SECONDS` 改回 60 即可。

## 排错速查（按当前状态更新）

| 现象 | 原因 | 处理 |
|---|---|---|
| 一键闭环返回 `Connection refused` | 服务没启动或窗口被关了 | 重新双击 `启动简历测试.bat`，保持窗口开着 |
| `screened_passed=0`、飞书没动静 | 简历缺 `专业：` / 技能不匹配 / 邮件进了垃圾箱 | 换用上面的样本 A 原文；检查 163 收件箱；看启动窗口日志里的 `ingest.candidate` 分数 |
| 飞书报 `open_id 无效` / `99991672` | `positions.yaml` 还是 `ou_mock_zhangwei`，或改了没重跑初始化 | 改成自己的 ou_，重跑 `初始化数据库.bat`，再点一键闭环 |
| `No module named 'lark_oapi'` | 老版 SDK 与代码不匹配 | 已安装 `lark-oapi` 并修正 requirements，当前不会再出现 |
| `code=99991672 im:resource:upload` | 应用缺「上传文件」权限，zip 发不出去（**文本消息不受影响，已能送达**） | 打开报错里的权限申请链接，勾选 `im:resource:upload`，**创建新版本并发布**，然后重跑闭环 |
| `feishu_message_id` 有值但 `ok=false` | 文本摘要已发成功，仅文件那一步失败 | 同上，开权限即可 |
| 邮件副本退信 | `supervisor.email` 是虚构域名 | 改成真实邮箱，不影响飞书推送 |
| `LOGIN failed` | 填了登录密码而非 16 位授权码 | 换授权码 |
| `553 Mail from must equal authorized user` | 发件地址与登录账号不一致 | 三处（`SMTP_USER`/`HR_MAILBOX`/`IMAP_USER`）保持一致 |
| `Unsafe Login` / `SEARCH illegal in state AUTH` | 旧版代码缺 ID 命令 | **已修复**，当前不会再出现 |

## 第 6 步（可选）：让机器人能"听懂"你在飞书里的回复

### 为什么直接回复没人理

发消息（机器人 → 你）和收消息（你 → 机器人）是**两条独立的链路**：

- 发消息：项目主动调飞书 API，已完全跑通；
- 收消息：飞书云端要把你的消息推给项目的 `POST /api/v1/feishu/webhook`。但服务跑在 `127.0.0.1:8000`，**飞书服务器访问不到你本机**，且开放平台没订阅「接收消息」事件，所以消息根本没送进来。

已用本地模拟事件验证过：**业务代码没问题**。模拟你发「你好」，服务立刻识别你是「张伟」主管，并生成回复「张总，我还没看懂您的安排，请按…格式回复我…本轮待反馈候选人：王小明」。

### 免公网的解法：飞书长连接（WebSocket）

新增 `scripts/feishu_ws_bridge.py` + `启动飞书长连接.bat`（**不改任何现有代码**）：长连接由本机主动连飞书，收到消息后转发给本地 webhook，之后全走项目原有逻辑。实测已成功连上 `wss://msg-frontier.feishu.cn/ws/v2`，事件转换结构也已验证。

**① 开放平台网页配置（一次性）**

1. 应用详情 → **事件与回调 / 事件订阅** → 订阅方式选 **「使用长连接接收事件」**（与填写 URL 二选一，选长连接就不用公网地址）
2. **添加事件**：`接收消息` / `im.message.receive_v1`（平台会提示补齐所需权限，按提示添加）
3. **创建版本并发布**（权限和事件变更必须发布才生效）

**② 本地双击两个窗口，都保持开着**

- `启动简历测试.bat`（服务）
- `启动飞书长连接.bat`（桥接，窗口显示 `connected to wss://...` 即成功）

**③ 去飞书回复，按格式说话**

随便回「你好」只会收到一条格式提示，不会推进流程。要触发完整闭环，回复例如：

```
请通知王小明，下周三下午 14:00 来公司面试
```

（回复里必须出现**本轮真实候选人姓名**，规则模式下没有「全部通过」这种简写。）

> ⚠️ **别照抄机器人回你的那句示例！** 它写的是「请通知张三、李四…」，但那两个名字不在你本轮名单里（本轮只有「王小明」），照抄会永远收到"我还没看懂"的提示。另外「全部通过」在 `LLM_MODE=off` 的规则模式下也不被识别（见下方实测表）。**回复里必须出现真实候选人姓名。**
>
> | 回复内容 | 解析名单 | 结果 |
> |---|---|---|
> | 请通知张三、李四，下周三下午 14:00 来公司面试 | `[]` | ❌ 死循环 |
> | 全部通过，下周三下午 14:00 面试 | `[]` | ❌ 失败 |
> | 请通知王小明，下周三下午 14:00 来公司面试 | `['王小明']` | ✅ 通过 |
> | 王小明，下周三下午 14:00 面试 | `['王小明']` | ✅ 通过 |
>
> 根因：`service/feedback.py:420` 的 `_format_hint()` 把示例名字写死成「张三、李四」，而 `service/extraction.py:80` 的 `match_roster_names()` 只按真实名单做字符串匹配；「全部通过」在规则抽取里没有实现。

机器人会回你确认消息，并给候选人发面试通知邮件（候选人是虚构邮箱，邮件会退信，属正常）。

> 若坚持用 webhook 回调模式，则需要把本机 8000 端口做内网穿透成公网 HTTPS 地址，再填进开放平台，并配置 `FEISHU_VERIFICATION_TOKEN` / `FEISHU_ENCRYPT_KEY`（当前 `.env` 里两项为空）。比长连接麻烦，本地测试不建议。
