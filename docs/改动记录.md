## 2026-11-13 · 数据库全面切 PostgreSQL（运行时 + Alembic + 外键 + 测试也走 PG）

**改了什么**

1. `DATABASE_URL` 从 SQLite 改为 PostgreSQL；引入 Alembic，建首个迁移 `0001_initial`（6 张业务表 + 7 条外键）。
2. 三个 model 补外键（`candidate` / `message` / `email_thread`，`ON DELETE SET NULL`）。
3. **测试库也改为 PostgreSQL**：自动派生 `hr_robot_test`、自动建库、每用例 `TRUNCATE` 清空、PG 没起自动拉起 docker。
4. `scripts/e2e_four_chains.py` 改用 PG 独立库 `hr_robot_e2e`，样例简历路径改为自动查找 `tests/testdata/`。

**为什么**：生产与测试必须同引擎，否则 PG 才有的字段长度 / JSON / 外键 / 序列问题测不出来；且要求「不用人工改配置」。

**改了哪些文件**：`.env`、`.env.example`、`requirements.txt`、`alembic.ini`、`migrations/*`、`core/db.py`、`tests/conftest.py`、
`scripts/e2e_four_chains.py`、`model/{candidate,message,email_thread}.py`、`README.md`、`AGENT.md`、`docs/DECISIONS.md`、
`docs/ops/database-setup.md`。

**验证**：`alembic upgrade head` / `alembic check` 通过；190 个测试连跑 3 次全绿；删库后首跑也全绿。

**遗留**：`messages.external_id` 仍不加唯一约束（加了会破坏「失败重试同 ID 并存」的幂等设计，挂 3 个测试）。

**详见**：`docs/quality/数据库切换PostgreSQL改动说明_20261113.md`

## 2026-11-13 · 修复 docx/pdf 简历解析成空 + 主管 open_id 填错

**改了什么**

1. `client/resume_parser.py`：文本提取改为「原生库优先、`unstructured` 兜底」（`.docx` → python-docx，`.pdf` → pypdf）。
2. `config/positions.yaml`：三个主管的 `feishu_open_id` 从群 `chat_id`（`oc_...`）改回个人 `open_id`（`ou_...`）。

**为什么**

1. 本机实测 `unstructured.partition()` 解析 docx 会卡住 >120 秒，而解析在 60 秒超时的子进程里跑 → 所有 docx/pdf 简历被强杀成空文本 → 抽取不到学历 → 被硬条件误判淘汰（BOSS 直聘的 docx 附件全军覆没）。
2. `oc_` 开头的是群 chat_id，用它反查主管永远查不到，导致飞书里「认人」失败、面试通知挂不起来（`supervisor_unknown`）。

**改了哪些文件**：`client/resume_parser.py`、`config/positions.yaml`。

**验证**：docx / pdf 解析从 >120s 超时变为 0.14s（403 / 430 字）；四条链路验收从 13/16 提升到 **16/16 通过**；190 个测试仍全绿。

**遗留**：原生库抽不出文本的文件（扫描件）仍会白等一次 60s 兜底超时。

**详见**：`docs/quality/数据库切换PostgreSQL改动说明_20261113.md` 第 5 节
