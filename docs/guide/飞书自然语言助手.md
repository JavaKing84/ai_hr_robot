# 飞书自然语言助手（Agent 层）

> 2026-11-13 新增。目标：主管在群里随便说人话，机器人都能听懂并办对事，
> 不再要求背固定句式。**模型只负责理解和表达，改库/发信仍走确定性代码。**

---

## 1. 它能听懂什么

| 你说的话 | 机器人做什么 |
|---|---|
| 「现在都有哪些候选人」「谁还没安排面试」 | 查名单 + 状态 + 分数 + 面试时间 |
| 「王耀国为什么是 100 分」「他哪项最弱」 | 摊开 `score_detail`：硬条件、加权命中、语义分、风险 |
| 「他会 Kubernetes 吗」「简历里有没有高并发」 | 读该候选人简历正文回答（截前 2500 字） |
| 「这轮收了多少份，通过几个」 | 状态统计 + 未淘汰名单 |
| 「你能干什么」 | 能力清单 |
| 「这俩都还行，安排后天上午十点半面试」 | 解析成名单 + 时间 → 生成面试通知（等 HR 确认后发送） |
| 「王耀国改到周四下午三点」 | 走改期流程（状态回到 `supervisor_feedback`，重新走一次确认闸门） |
| 「确认发送」「取消」 | 放行 / 作废挂起的面试通知 |
| 「把陈思远淘汰掉，不合适」 | 标记淘汰，**不发任何通知**（项目口径：不发感谢信） |

听不懂时不会乱动：判成 `unknown` 只回一句引导，不会误发邮件。

## 2. 架构（三层，任一层挂掉都不影响其余）

```
飞书消息
   │
   ├─ ① 路由  AgentService.plan()      模型输出 {intent, names, time_text, question}
   │        姓名接地：写操作的姓名必须能在该主管职位下查到，否则丢弃
   │
   ├─ ② 检索  AgentService._facts()     按意图查库，拼成紧凑 JSON（候选人/分数/统计/简历片段/近 6 条对话）
   │
   └─ ③ 表达  AgentService._compose()   模型只依据 ② 的数据组织人话；模型挂了降级成规则摘要
                │
                └─ 写操作 → FeedbackService 原有确定性逻辑（发通知/改状态/记事件）
```

关键设计：**模型永远拿不到数据库句柄**。它只能说「我要安排王耀国 2026-11-14 15:00 面试」，
真正写库的是 `FeedbackService._handle_schedule`，沿用原来的接地校验、审批闸门与留痕。

## 3. 接入步骤（本地开发：长连接，不需要公网地址）

1. **飞书开放平台 → 事件订阅**：选择「使用长连接接收事件」，订阅 `im.message.receive_v1`。
2. **权限**（缺一不可）：
   - `im:message:receive_v1`（收消息）
   - `im:message:send_as_bot`（发文本）
   - `im:resource:upload`（发简历压缩包，缺了会 99991672）
3. **发布应用版本**，并把机器人拉进群（本项目已在 `2026-华为ICT大赛--智能员工HR` 群）。
4. **`.env` 配置**：

```ini
FEISHU_MODE=live
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
FEISHU_CHAT_ID=oc_xxx          # 填了这个就走群，不再需要 webhook 占位
FEISHU_PUSH_TARGET=group
HR_FEISHU_OPEN_ID=ou_xxx       # HR 本人 open_id：确认/取消审批 + 以 HR 身份提问

LLM_MODE=auto
# DeepSeek 官方（2026-11-13 实测：路由 1.5s / 作答 1.8s，JSON 直接进 content）
LLM_PROVIDERS=[{"name":"deepseek-flash","model":"openai/deepseek-flash","api_base":"https://api.deepseek.com/v1","api_key":"sk-xxx"},{"name":"deepseek-v4-pro","model":"openai/deepseek-v4-pro","api_base":"https://api.deepseek.com/v1","api_key":"sk-xxx"}]
LLM_TIMEOUT_SECONDS=90
```

> 换模型前先 `GET {api_base}/models` 看真实 ID。DeepSeek 2026-11-13 实测：`/models` 只列
> `deepseek-flash` 与 `deepseek-v4-pro`；`deepseek-chat` / `deepseek-reasoner` 虽不在列表里，
> 但**仍能正常返回 200**（兼容别名）。新接入按 `/models` 列出的事配，别依赖未列出的别名。
> `model` 里的 `openai/` 前缀是给 litellm 认协议的，httpx 直连分支会自动剥掉。

5. **启动两个进程**：

```bash
# 业务服务
./.venv/Scripts/python.exe -m uvicorn factory.app:create_app --factory --port 8000
# 飞书长连接桥（把 WS 事件转发到本地 /api/v1/feishu/webhook）
./.venv/Scripts/python.exe scripts/feishu_ws_bridge.py
```

之后在群里 @机器人 说人话即可。

## 4. 关于 `disable_thinking`

vLLM 部署的 Qwen3 默认「先写一大段推理再给答案」：`max_tokens` 偏小时 `content` 直接是
`null`，只能从 `reasoning` 里捞 JSON——而提示词里的 few-shot 示例也在 `reasoning` 里，
**极易把示例当成结果**（比解析失败更危险）。

供应商配置加 `"disable_thinking": true` 后，请求会带
`chat_template_kwargs: {"enable_thinking": false}`，实测：同一条消息从 48 秒降到 2 秒，
且不再出现「复述提示词」的假 JSON。

换成 DeepSeek / 阿里百炼 / OpenAI 时删掉这个键即可（它们不认这个字段，但也不影响）。

## 5. 排查

| 现象 | 原因与处理 |
|---|---|
| 群里 @ 了没反应 | 事件订阅没选长连接 / 应用版本没发布 / `feishu_ws_bridge.py` 没跑 |
| 回「请按下面格式回复」 | 路由判成 `unknown`：换更明确的说法，或看日志 `agent.route_failed` |
| 回「发送者不是已登记的主管」 | 发送者 open_id 既不在 `supervisors` 表也不等于 `HR_FEISHU_OPEN_ID` |
| 发文件报 `99991672` | 应用缺 `im:resource:upload` |
| 回复慢（10s+） | 模型在思考：确认 `disable_thinking` 已生效；或换更快的模型（`deepseek-flash` 实测 2–3s） |
| `400 model_not_found` | `.env` 里的模型 ID 已下线：`GET {api_base}/models` 查真实 ID 再改 |
| `prepared statement ... does not exist` | 走了云厂商连接池：`DB_STATEMENT_CACHE_SIZE=0` |

## 5.1 已知边界

- **不能给「还没派发」的候选人排期**：主管名单只含 `dispatched` / `supervisor_feedback` /
  `interview_notified` / `reschedule_pending`。刚筛选通过（`screened_passed`）的人要等 HR 派发后
  才进主管视野，此时说「安排刘凯面试」会回「本轮没有待反馈的候选人」。这是产品口径，不是解析失败。
- **改期不会直接发第二封邮件**：改期后状态回到 `supervisor_feedback`、通知重新进确认闸门，
  HR 回「确认发送」才投递。
- **简历问答只看前 2500 字**，超长简历后半段搜不到。

## 6. 代码索引

| 文件 | 职责 |
|---|---|
| `schema/agent.py` | `AgentIntent` 枚举、中文别名归一化、`AgentPlan` / `AgentFacts` |
| `prompt/agent.py` | 路由提示词（含 few-shot）、作答提示词（只准引用事实） |
| `service/agent.py` | `plan()` 路由、`_facts()` 检索、`_compose()` 表达、`answer()` 发消息留痕 |
| `service/feedback.py` | 入口编排：读类交给 Agent、写类走原逻辑、`_handle_reject` 淘汰 |
| `client/llm.py` | `complete_json` / `complete_text`，litellm 与 httpx 双通道 |
